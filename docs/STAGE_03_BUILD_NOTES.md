# ULTRA Stage 03 — moderation, admin controls and pilot hardening

## Implemented in source

- Development records now default to `PENDING`; public `developments.byId` and `developments.list` expose only `APPROVED` developments. The public unit list remains restricted to `LIVE` listings.
- Admin development queue and review mutation support `APPROVED` / `REJECTED`, reviewer identity, timestamp and review note.
- `AdminAuditLog` records sensitive administrator and development moderation actions.
- `SUPER_ADMIN` can create an administrator by name and phone, promote an existing BUYER account, list admins, inspect recent audit events and demote an ADMIN. Demotion cannot target self or a SUPER_ADMIN, requires a reason, preserves at least one active ADMIN and revokes outstanding refresh tokens.
- Browser image uploads are resized to max 1600px and WebP quality 0.82 where the browser supports it and the output is smaller. Non-image files and verification documents retain their original format.
- Listing and approved development routes now emit Open Graph / Twitter metadata from server-side database queries for WhatsApp link previews.
- `/api/health` performs a database connectivity check and returns 503 when the database is unavailable.
- Integration coverage added for development publication gates, administrator management/audit events and the Home Services provider-to-customer request/messaging/admin monitoring path.

## Migration baseline — not generated in this environment

The repository has no installed workspace dependencies, no pnpm executable and no Docker/Postgres service in this execution environment. A complete SQL migration must be generated by the pinned Prisma CLI, not hand-authored or represented as verified.

Run on the development machine / CI:

1. `corepack enable && corepack prepare pnpm@9.7.0 --activate`
2. `pnpm install`
3. `pnpm db:generate`
4. `bash scripts/generate-migration-baseline.sh`
5. Review `packages/db/prisma/migrations/20261123000000_init/migration.sql`.
6. `pnpm verify:migration`
7. `pnpm test:unit && pnpm test:integration`
8. `pnpm lint && pnpm typecheck && pnpm --filter @ultra/web build`

The baseline script intentionally refuses to overwrite an existing migration. It is appropriate only where the database is new and no prior migration history exists. If any environment already has production data, create and review a non-destructive migration plan against that database instead of applying an initial baseline blindly.

## Staging configuration still required

- `NEXT_PUBLIC_HOME_SERVICES_ENABLED=true` on the web build.
- `HOME_SERVICES_ENABLED=true` on API and mobile build runtime/configuration.
- `NEXT_PUBLIC_SUPPORT_EMAIL`, `NEXT_PUBLIC_SUPPORT_WHATSAPP`, `SUPPORT_EMAIL`, and `SUPPORT_WHATSAPP` set to approved operational contacts.
- Staging `DATABASE_URL`, `REDIS_URL`, Termii test credentials, Paystack test credentials, R2 public-media and private-KYC buckets, `SENTRY_DSN`, and PostHog credentials.
- Configure Sentry alert rules for new/unhandled errors and webhook failures; configure an external uptime monitor against `/api/health`. These are provider-console actions and cannot be completed by repository code alone.
- Verify one SMS, payment test webhook, public photo upload, private KYC access denial, push notification, Sentry event and PostHog event on a real staging environment.

## Important pilot safety notes

- Keep live Paystack charges disabled until webhook idempotency tests pass and business verification is complete. Manual lead-credit grants remain the pilot fallback.
- Home Services must be enabled consistently across the web, API and mobile pilot builds; all other environments remain disabled by default.
- `ADMIN` creation is restricted to `SUPER_ADMIN`. The new admin must complete the ordinary phone-code sign-in; no OTP bypass or static password is created.
- `verifiedAt` / `businessVerified` semantics should be checked in the trust-copy audit against the actual evidence reviewed by ULTRA.

## Additional hardening in this source update

- Editing an already-approved development resets it to `PENDING` and clears the prior reviewer decision, so edits cannot bypass moderation.
- A LIVE unit may remain discoverable as an individual listing, but its parent development metadata is stripped from the public listing response until the parent is approved.
- Admin and super-admin authorization now re-checks the current database role on every sensitive request. A demoted admin's still-valid access token no longer grants admin access.
- Paystack webhook processing failures are reported through the existing Sentry wrapper and return HTTP 500 so the payment provider can retry delivery.
- `scripts/check-pilot-env.mjs` and `pnpm check:pilot-env` provide a missing-variable preflight. Passing this check proves only that values are present, not that credentials or integrations work.
